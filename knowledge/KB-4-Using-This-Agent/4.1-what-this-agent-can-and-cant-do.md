# What This Agent Can and Can't Do (FAQ)

## Summary
The ADO Backlog Agent helps the [PROJECT] team **find, create, update, and comment on** Azure DevOps work items through a guided, confirm-before-write conversation. It reads all four work-item types (Epic, Feature, User Story, Task) but **creates and edits only Features, User Stories, and Tasks** — never Epics, and it never deletes anything. Every change is previewed and only written after you confirm.

**Also known as:** what can the agent do, agent capabilities, agent help, what can I ask, agent FAQ, can it create epics, can it delete, how do I use the backlog agent.

## What it can do
- **Find and read** existing items — search the backlog by text, type, area, state, or assignee; open one item to see its full fields, parent, and children; check whether something similar already exists before you create a duplicate.
- **List what's assigned to you** — ask "show me my work items" (or name a teammate, e.g. "what's assigned to jane@org.com?"). Shows active items by default, grouped by state; ask for closed items or a specific type to narrow.
- **Create** Features, User Stories, and Tasks — either a single item or a whole Feature → Story → Task tree in one request — after a short quality interview and a duplicate check.
- **Update** existing Features, User Stories, and Tasks — change fields such as description, acceptance criteria, priority, estimates, value area, or release/deploy/feature-flag notes.
- **Comment** — add a discussion comment to an existing Feature, User Story, or Task.

## What it can't (and won't) do
- **Create Epics.** It builds only Features, User Stories, and Tasks. If you need an Epic, it can instead create a Feature under an existing Epic.
- **Edit or comment on Epics.** Epics are read-only — the agent can show you an Epic and its children, but it makes no changes to one.
- **Delete anything.** There is no delete capability.
- **Work outside the single configured project.** It operates in one Azure DevOps project.

## How to phrase a request
Plain language works. Helpful patterns:
- *Find:* "Find my User Stories in area [X]", "What's under Feature 1234?", "Has anyone created a Story for [topic]?"
- *My items:* "Show me my work items", "What am I working on?", "List my open tasks", "What's assigned to jane@org.com?"
- *Create:* "Create a Feature for [outcome], with a couple of Stories", "Add a Task under Story 5678 to [do X]."
- *Update:* "Update the acceptance criteria on Story 4321", "Set the release notes on Feature 1234."
- *Comment:* "Add a comment to Task 9999 that [note]."

The more specific the outcome and parent you name, the fewer follow-up questions you'll get.

## What it will ask you for
Because the agent enforces a quality bar, it interviews you for the fields each type needs:

| Type | It will ask for | It may nudge for |
|---|---|---|
| **Feature** | Title, Description (the outcome/value), Acceptance Criteria, Value Area, Team, Area Path, and the parent Epic if one applies | Story Points, Priority, Risk, Effort, Iteration |
| **User Story** | Title (user-voice), Description, Acceptance Criteria, Value Area, Team, Area Path, and the parent Feature | Story Points, Priority, Risk, Effort, Iteration |
| **Task** | Title (an actionable verb), Description, and the parent User Story | — |

If a field is weak or missing, the agent suggests an improvement; you can accept it or override and proceed — **except the work-item type, which can never be set to Epic.**

## What happens before anything is written
Nothing is created or changed until you confirm. For a create, the agent shows a preview of the whole tree (flagging any weak fields and possible duplicates); for an edit, it shows an old → new diff. You click **Confirm** to write or **Cancel** to discard.

## If your request is out of scope
For anything outside finding or working with work items, the agent will say so and point you to **[ORG: contact]**.
